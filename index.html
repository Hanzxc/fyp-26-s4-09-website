CSIT321 Final Year Project

Find the weak spots in face login before attackers do

Two Android apps for developers who use face authentication. The Biometric Test App runs face login attempts and times every step. The Security Analyst Tool reads those timings, looks for leaks and photo spoofing, and explains each fix in plain language. Then you switch the fixes on, test again and see whether they worked.

Timing leak

Near misses take 195 ms longer to reject than a stranger's face.

Fix: pad every rejection to the same response time.

A University of Wollongong final year project, taught at the Singapore Institute of Management

Where face login goes wrong

Most apps hand face login to the phone and trust whatever comes back, so nobody checks how long a rejection takes or whether a photo would get through.

Timing leaks

If a near match takes longer to reject than a stranger's face, an attacker who times each try learns something from every failure.

Photo spoofing

A face pipeline without a proper liveness check may accept a printed photo, or a picture held up on another phone.

Hard to see

Android's built-in face prompt hides how it decides, and many app developers have no security background to read the numbers anyway.

How it works

  1. 01

    Test

    A tester runs face login attempts with participants who have given consent. The Biometric Test App records the result and timing of every attempt.

  2. 02

    Export

    Each run is saved as a telemetry file with a format version and a checksum, so a file that has been edited gets caught on import.

  3. 03

    Analyse

    The Security Analyst Tool imports the file, runs the statistics, and lists what it found with advice on how to fix each issue.

  4. 04

    Compare

    The tester turns on the fixes in the Test App and runs the same tests again. The Analyst Tool puts the two runs side by side to show which weaknesses are gone.

Who it's for

App developers who use face login but have little security training. The tester and the analyst are often the same person.

Tester

Biometric Test App

Enrols participants, sets the match threshold, picks a scenario and runs the attempts, then exports each run.

Participant

Biometric Test App

Reads the consent screen and agrees before any face is captured. The tester does the rest, and can be a participant too.

Analyst

Security Analyst Tool

Imports runs, reads the findings and recommendations, and exports a PDF report to share with the team.

The two apps

Both run fully on an Android phone. Results move from one app to the other as an exported file.

Biometric Test App

For testers and participants

  • Records participant consent before the camera turns on
  • Enrols a participant's face, and lets the tester re-enrol or delete participants
  • Labels each attempt as genuine, impostor or photo spoof
  • Lets the tester change the match threshold to see how strict matching affects security
  • Times every processing step and saves the outcome of every attempt
  • Runs many attempts in a row to collect enough samples and test repeated guessing
  • Exports each run as a telemetry file

Mitigation switches, off by default

  • A fixed response time, so timing no longer shows how close a face came
  • A blink check that rejects printed and on-screen photos
  • A lockout after too many failed attempts

Security Analyst Tool

For security analysts and app developers

  • Imports telemetry from the Test App, or from any app that uses the same format
  • Lists every imported session and shows summary statistics for each one
  • Charts the timings and match scores
  • Tests whether accepted and rejected attempts take different amounts of time
  • Reports how often photo spoofs got through, the false accept and false reject rates, and whether repeated failures were limited
  • Lists findings by severity, each with a recommended fix
  • Compares a run with the mitigations off against a run with them on
  • Exports a PDF report and deletes sessions that are no longer needed

Five attacks it tests against

Each one comes from how face login gets broken in practice. The first three are checked from the telemetry; the last two are blocked by how the apps handle data.

Attack What the tool does Fix or safeguard

Timing inference

The attacker times each failed try. If near misses take longer to reject, every failure tells them how close they came.

Runs a statistical test on accepted and rejected attempts to see whether their timings differ.

Give every attempt the same response time.

Photo spoofing

The attacker holds up a photo of the victim, taken from social media.

Counts how many photo spoof attempts were accepted.

Add a liveness check, such as asking for a blink.

Repeated guessing

The attacker keeps trying until one attempt passes.

Checks whether failed attempts in a row were ever limited.

Lock face login after too many failures.

Stored face data

Someone with a lost or unlocked phone opens the Test App's data or its exported files.

Keeps participant screens behind a PIN or the phone's screen lock.

Face data is encrypted with a key in the Android Keystore, and exports never contain faces.

Tampered telemetry

A telemetry file is edited after export so the analysis hides a weakness.

Checks the format and checksum of every file on import.

A file that fails either check is rejected and never saved.

Private by design

The apps handle people's faces, so they keep as little as they can and follow Singapore's Personal Data Protection Act (PDPA).

Stays on the phone

There is no server and no internet connection. Test data only leaves the device when someone exports it.

Consent comes first

A participant reads what face data is collected and agrees before the camera captures anything.

Codes instead of names

Participants are known by a code. Exported files and PDF reports carry those codes, never face images or face embeddings.

Encrypted, logged and deletable

Face embeddings are stored encrypted. Both apps keep a log of enrolments, imports, exports and deletions, and any participant or session can be deleted at any time.

How it's built

Native Android, with the face model running on the phone.

Both apps follow a Boundary, Control, Entity structure, so screens, logic and data can change separately. Recommendations come from a rules file, so the advice can be updated without touching code. The telemetry format has a version number, which keeps older exports readable.

Tools like MobSF and NowSecure scan for general mobile app weaknesses. This project looks only at biometric login and is meant to sit next to them.

Scope and what's next

The requirements were written up in November 2026. Building the apps comes next.

First release

  • The Biometric Test App and the Security Analyst Tool
  • Face authentication
  • Checks for timing leaks, photo spoofing, error rates and attempt limits
  • Plain-language recommendations from a rules file

Stretch goals

  • Fingerprint and other biometric methods
  • Recommendations written by a large language model, behind the same interface as the rules

The tool only reports the weaknesses it has checks for. It won't discover new kinds of vulnerability.
